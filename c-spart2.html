1Introduction to Client/Server Architecture

The web is the best-known client/server system. Two programs share the work: one asks for documents, the other stores and delivers them.

Web client
A program that sends requests for documents to a web server, for example a web browser (Chrome, Firefox, Safari, Edge) or a mobile app.
Web server
A program that receives requests and sends back the requested documents, for example Nginx, Apache HTTP Server or Microsoft IIS.
Protocol
The agreed language both sides use. On the web it is HTTP (HyperText Transfer Protocol), today almost always as HTTPS, which wraps HTTP in TLS encryption.
URL
The address of a document, such as https://www.example.edu/history.html: the protocol (https), the server's name (www.example.edu) and the path to the document (/history.html).

A distributed architecture means that a client program may be running on a completely separate machine from that of the server. Because the task of document storage is left to the server and the task of document presentation is left to the client, each program can concentrate on those duties and progress independently of each other.

Example of "progress independently"

A new browser version can add dark mode or faster rendering without any change to millions of web servers, and a website can move to a new server or database without anyone reinstalling their browser. The two sides only have to keep speaking the same protocol.

Analogy

A library. You (the client) fill in a request slip with a book's call number (the URL). The librarian (the server) fetches the book from the stacks (storage) and hands it over. You read it at your own desk in your own way (presentation). The library does not care how you read; you do not care how the shelves are organised.

Key idea

Separation of duties: the server stores, the client presents. That split is what lets each side be improved, replaced or scaled on its own.

The process explained

  1. Running a web client, the user selects a hyperlink in a piece of hypertext connecting to another document, "The History of Computers", for example.
  2. The web client uses the address associated with that hyperlink to connect to the web server at a specified network address and asks for the document.
  3. The server responds by sending the text and any other media within that text (pictures, sounds, or movies) to the client, which the client then renders for presentation on the user's screen.

What happens underneath

Those three steps hide several smaller ones that are worth knowing for exams and for troubleshooting:

StageWhat happensProtocol
Name lookupThe browser turns the server name (www.example.edu) into an IP address.DNS (usually UDP port 53)
ConnectThe browser opens a connection to the server's IP address on port 443.TCP three-way handshake, or QUIC for HTTP/3
SecureThe server proves its identity with a certificate and both sides agree on encryption keys.TLS 1.3
RequestThe browser sends GET /history-of-computers.html with headers.HTTP
ResponseThe server returns a status code (200 OK), headers and the HTML.HTTP
Extra requestsThe HTML refers to images, CSS and scripts; the browser requests each one, often in parallel on the same connection.HTTP/2 or HTTP/3
RenderThe browser builds the page and displays it.(inside the client)
Common mistake

Thinking one click means one request. A typical page needs dozens of requests: the HTML first, then every image, stylesheet, font and script it mentions. That is why HTTP/2 and HTTP/3, which carry many requests at once over one connection, make pages load faster than HTTP/1.1.

Try it

Open your browser's developer tools (F12), choose the Network tab and reload any page. Each row is one request/response pair. The "Protocol" column shows h2 (HTTP/2) or h3 (HTTP/3).

Exam tip

If asked "describe how a client obtains a web page", write the three classic steps (select link → connect and request → server sends, client renders), then add DNS lookup and HTTPS to show you know how it works today.

3Advantages and Disadvantages

Putting data and services on a central server has clear benefits, and the same centralisation causes the main weaknesses.

Advantages

  • Centralised management: easier network administration, maintenance and backups, because data and settings live in one place.
  • Scalability: resources (CPU, memory, storage, more servers) can be added as demand grows, usually without changing the clients.
  • Enhanced data sharing: data is immediately available to all authorised users; everyone sees the same, current copy.
  • Location independence: users can access applications from anywhere with a network connection and a client.
  • Improved security control: access rights, patches and monitoring are managed centrally.

Disadvantages

  • Server cost: requires investment in hardware, software, licences and skilled administrators.
  • Complex configuration: setup and maintenance can be complicated.
  • Single point of failure: if the only server goes down, the service it provides becomes unavailable to every client.
  • Traffic congestion: the server can become overloaded when too many requests arrive at once (including deliberate denial-of-service attacks).
  • Attractive target: one server holding everyone's data is worth attacking, so a single breach can expose all users.
Correction

Older notes say "if the server goes down, the entire network fails" and that scaling happens "without affecting performance". More precisely: the network keeps working but the service stops; and adding resources helps only up to a point, because the database or the network link often becomes the next bottleneck.

How real systems reduce the disadvantages

DisadvantageCommon mitigation
Single point of failureSeveral servers behind a load balancer; database replicas; automatic failover
Traffic congestionLoad balancing, caching, content delivery networks (CDNs), rate limiting
Server costCloud hosting: rent capacity and pay for what you use
Attractive targetEncryption (HTTPS, encrypted storage), firewalls, patching, least privilege, monitoring

Client/server vs peer-to-peer

The alternative is peer-to-peer (P2P), where every machine is both client and server and shares its own resources directly with others (for example BitTorrent).

Pair each disadvantage with a mitigation. "Single point of failure, mitigated by redundant servers and load balancing" scores better than just "single point of failure".

4Different Types of Servers

Servers are classified by the services they provide. Here are the most common types:

File server

Used for sharing files (documents, media, images) across a network. Designed primarily for storage and retrieval of files requested by clients. Uses protocols such as SMB (Windows shares) or NFS.

Database server

Provides database services to other computers. Works with query languages like SQL: the client sends a query, the server runs it and returns only the matching rows. Examples: Oracle, Microsoft SQL Server, PostgreSQL, MySQL.

Transaction server

Divides work into individual operations called transactions, each completed fully or not at all. Used in Online Transaction Processing (OLTP) systems such as payments, ticket booking and stock trading.

Groupware server

Provides applications for collaboration (shared calendars, mail, shared databases and documents, electronic meetings). Examples: Microsoft Exchange; today often cloud services such as Microsoft 365 or Google Workspace.

Web server

Handles the HTTP protocol and serves static content. Retrieves files from the server's storage and sends them to clients unchanged. Examples: Nginx, Apache HTTP Server, IIS.

Web application server

Extends web servers to support dynamic content by mixing data with templates or accessing databases, and runs the business logic. Examples: Apache Tomcat, WildFly, Node.js, Spring Boot, Django.

Static content
A file that is the same for every visitor, sent as-is: a logo, a CSS file, a PDF timetable.
Dynamic content
A page built at request time, different per user or per moment: your grades, your shopping basket, search results.
OLTP
Online Transaction Processing: many short, concurrent transactions that must be fast and never corrupt data.

Analogy

A web server is a shop assistant handing you pre-packed items from a shelf. An application server is a cook who prepares your order to your specification, fetching ingredients (data) from the store room (database).

In practice

Real deployments usually put both together: Nginx in front serves static files and handles HTTPS, and forwards dynamic requests to the application server behind it. This setup is called a reverse proxy.

5Knowledge Check

Test your understanding of client/server architecture. Each answer shows why it is right.

Quiz: how client/server works

Q1What is the primary role of a web client?

A web client's main function is to send requests to a web server and display (render) the content it receives. Storing documents is the server's job; processing transactions belongs to transaction and database servers.

Q2Which protocol is primarily used for communication between web clients and servers?

HTTP (in practice HTTPS) is the application-layer protocol of the web. TCP is a transport-layer protocol that carries HTTP/1.1 and HTTP/2, but it is not the web's own protocol; HTTP/3 does not even use TCP. FTP transfers files and SMTP sends mail.

Q3What is a key disadvantage of the client/server model?

If the only server fails, the service it provides becomes unavailable to every client. The other three options are advantages of the model.

Q4Which type of server is specifically designed to handle dynamic content?

A web application server generates content per request by combining data with templates and running business logic. Database servers store and query data; transaction servers guarantee all-or-nothing operations; file servers store files.

Q5What is the main advantage of centralized management in client/server architecture?

With data and services in one place, administrators back up, patch and control access once instead of on every machine. It does not lower hardware cost (servers cost money) and it still needs a network.

Q6In a distributed architecture, the client and the server:

Distributed means the parts can run on different machines and cooperate over a network. Because they only share a protocol, they can use different languages and be updated independently.

Q7Before the browser can connect to www.example.edu, what must happen first?

Computers connect to IP addresses, not names. DNS resolves the name first; only then can the browser open a TCP (or QUIC) connection and send the HTTP request.

Q8The status line HTTP/1.1 200 OK means:

2xx codes mean success; 200 OK is the normal answer to a successful GET. Client errors are 4xx (such as 404), redirects are 3xx (such as 301), and an overloaded server answers 503.

Q9True or false: a web page normally arrives as one single response containing the HTML, images and styles together.

The first response is the HTML. The browser then sends separate requests for each image, stylesheet, script and font the HTML refers to. HTTP/2 and HTTP/3 speed this up by carrying many of these requests in parallel on one connection.

Q10Which is the best way to reduce the single-point-of-failure risk?

Redundancy removes the single point: if one server fails, the load balancer sends requests to the others. Client speed and HTTP versus HTTPS do not affect server availability, and moving data to clients gives up the benefits of client/server.

Summary

  • A web client (browser) requests documents; a web server stores and sends them. The server stores, the client presents.
  • Distributed architecture: client and server can run on separate machines and evolve independently, as long as they share the protocol (HTTP/HTTPS).
  • Getting a page: select a link → DNS lookup → connect (TCP or QUIC) and TLS → HTTP request → response → extra requests → render.
  • Advantages: central management, scalability, data sharing, location independence, central security control.
  • Disadvantages: cost, complexity, single point of failure, congestion, attractive target; reduced with redundancy, load balancing, caching and security controls.
  • Server types: file, database, transaction (OLTP), groupware, web (static) and web application (dynamic).
