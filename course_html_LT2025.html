1Foundations of the Client/Server Model

Two versions of this lesson

This is the short Course Overview. The Extended Edition covers the same seven sections in much more depth, with full Java code (multi-threaded servers, UDP, HTTP, JDBC transactions, three RMI programs), diagrams and a quiz after every section.

What is client/server?

Client/server is a way of organising a networked system in which every program plays one of two roles. A client asks for something. A server waits for requests and provides the service: files, printers, database data, computing power or web pages. Clients rely on servers for those shared resources.

  • Clients: PCs and workstations running user applications. Today that also means phones, browsers, smart TVs and IoT devices.
  • Servers: computers that store and manage shared files, data and applications. In practice a server is often a virtual machine or container in a data centre or cloud, and many servers run on one physical host.
Analogy

A restaurant. You (the client) read the menu and place an order. The kitchen (the server) prepares it and sends it back. The waiter and the order slip are the protocol: an agreed format both sides understand. The kitchen serves many tables at once, and you never need to know how it is organised inside.

How they communicate

Clients and servers exchange messages using a request-response pattern. Because the two programs are separate processes (usually on separate machines), this exchange is a form of Inter-Process Communication (IPC). Both sides must speak a common protocol, such as HTTP. Because many clients connect at the same time, servers use scheduling (threads, thread pools or event loops) to handle many requests concurrently.

Client— request →Server— response →Client
Key idea

The client always initiates; the server listens and responds. "Client" and "server" are roles played by programs, not types of hardware.

Advantages and disadvantages

Advantages

  • Centralised management: data, backups and updates live in one place.
  • Scalability: add clients freely; upgrade or add servers when load grows.
  • Enhanced data sharing: every authorised user sees the same, current data.
  • Improved security: access control is enforced at the server, not on each PC.

Disadvantages

  • Server cost: hardware, licences and skilled administrators.
  • Complex configuration: networking, permissions and services must be set up correctly.
  • Single point of failure: if the only server goes down, nobody can work (reduced with redundancy and load balancers).
  • Traffic congestion: too many simultaneous requests can overload the server or the network.
Common mistake

Saying "a server is a powerful computer". A server is any program that provides a service. A laptop running a small web server for testing is a server; a powerful workstation that only runs a browser is a client.

Exam tip

When asked to compare client/server with peer-to-peer, say: in client/server the roles are fixed and resources are centralised; in peer-to-peer every node can be both client and server and resources are spread across the peers.

2-tier, 3-tier and N-tier

A tier is a separate layer of the system, often on its own machine. The usual three jobs are presentation (the user interface), business logic (the rules) and data (storage).

  • 2-tier: Client + Database Server. The client holds the interface and most of the logic.
  • 3-tier: Client + Application Server + Database Server. The logic moves to the middle tier.
  • N-tier: an extended architecture with specialised components such as load balancers, caches, web servers, message queues or microservices.
Client (UI)→Application server (logic)→Database server (data)

2-tier vs 3-tier comparison

Feature2-Tier3-Tier
System administrationMore logic on each client to manageCentrally managed on the server
PerformancePoor (many SQL statements over the network)Good (only service requests and responses)
ScalabilityPoor / lowExcellent (distribute load across servers)
Application reusePoor (application lives on the client)Excellent (reuse services and objects)
Ease of developmentHigh (simple)More complex
Example

An online shop: the browser shows products (presentation), a Java or Node.js application computes prices, stock and discounts (logic), and PostgreSQL stores orders (data). That is 3-tier. Add a load balancer and a cache in front of several application servers and it becomes N-tier.

Exam tip

"Why is 3-tier faster than 2-tier?" In 2-tier the client sends many raw SQL statements across the network. In 3-tier it sends one service request ("place order"), and the many SQL statements run between the application server and the database, which sit close together.

3Core Communication Technologies

Sockets and ports

A socket is the programming interface a process uses to send and receive data over the network. A socket is identified by an IP address (which machine) plus a port (which program on that machine).

Analogy

The IP address is the street address of an apartment building; the port is the apartment number. The post office (the network) delivers to the building, and the port says which resident gets the letter.

Port numbers are grouped into ranges: 0–1023 well-known (system services), 1024–49151 registered, and 49152–65535 dynamic or ephemeral (picked automatically for the client side).

ServicePortTransport
HTTP80TCP
HTTPS443TCP (HTTP/1.1, HTTP/2); UDP for HTTP/3
FTP21 control, 20 data (active mode)TCP
SSH / SFTP22TCP
SMTP25 (server to server); 587 for mail submissionTCP
DNS53UDP for most queries; TCP for large answers and zone transfers

TCP vs UDP

TCP (Transmission Control Protocol) is connection-oriented: it sets up a connection with a three-way handshake (SYN, SYN-ACK, ACK) and then guarantees reliable, ordered delivery. UDP (User Datagram Protocol) is connectionless: it sends independent packets (datagrams) with no guarantees, which makes it lighter and faster. UDP is used for voice, video, DNS and DHCP, and also underneath QUIC, which carries HTTP/3.

FeatureTCPUDP
ConnectionConnection-oriented (handshake first)Connectionless
ReliabilityHigh (error checking, acknowledgements, retransmission)Low (no delivery guarantee; checksum only)
OrderingData arrives in the order sentPackets may arrive out of order
SpeedSlower (more overhead)Faster (less overhead)
Header size20–60 bytes8 bytes
UsageHTTP/1.1, HTTP/2, HTTPS, FTP, SMTP, SSHDNS, DHCP, VoIP, video streaming, online games, QUIC (HTTP/3)
Common mistake

"UDP is unreliable, so it is bad." UDP is chosen on purpose when late data is useless (a voice call cannot wait for a retransmission) or when the application adds its own reliability, as QUIC does.

Java networking

Java's java.net package provides comprehensive networking support:

  • InetAddress represents an IP address (IPv4 or IPv6) and can resolve host names through DNS.
  • Socket (client) and ServerSocket (server) handle TCP communication.
  • DatagramSocket and DatagramPacket handle UDP communication.
  • For web requests, modern Java (11+) adds java.net.http.HttpClient, which supports HTTP/1.1 and HTTP/2.

TCPClient.java: sends one line, prints the server's reply

// Java TCP Client Example
import java.io.*;
import java.net.*;

public class TCPClient {
    public static void main(String args[]) throws Exception {
        String sentence;
        String modifiedSentence;
        BufferedReader inFromUser = new BufferedReader(
            new InputStreamReader(System.in));

        Socket clientSocket = new Socket("localhost", 6789);

        DataOutputStream outToServer = new DataOutputStream(
            clientSocket.getOutputStream());

        BufferedReader inFromServer = new BufferedReader(
            new InputStreamReader(clientSocket.getInputStream()));

        sentence = inFromUser.readLine();
        outToServer.writeBytes(sentence + '\n');
        modifiedSentence = inFromServer.readLine();
        System.out.println(modifiedSentence);
        clientSocket.close();
    }
}
  1. Connect: new Socket("localhost", 6789) performs the TCP handshake with a server listening on port 6789.
  2. Wrap the streams: the output stream sends bytes; the input stream is wrapped in a BufferedReader so we can read whole lines.
  3. Send: writeBytes(sentence + '\n'). The newline matters: the server's readLine() waits until it sees one.
  4. Receive and close: read the reply line, print it, close the socket.
Tip

writeBytes keeps only the low 8 bits of each character, so it is fine for plain ASCII but breaks Arabic or accented text. In new code use a PrintWriter or an OutputStreamWriter with StandardCharsets.UTF_8.

4Application Protocols (Case Studies)

HTTP

HTTP (HyperText Transfer Protocol) is an application-level protocol for distributed, collaborative, hypermedia information systems: the protocol of the Web. A client sends a request (method, path, headers, optional body); the server returns a response (status code, headers, body).

Key features:

  • Stateless: each request is independent; the server does not remember earlier requests. Applications add state with cookies, sessions or tokens.
  • Media independent: any kind of data (HTML, JSON, images, video) can be sent, as long as both sides understand the Content-Type.
  • Connection handling (updated): older notes call HTTP "connectionless" because HTTP/1.0 closed the connection after each response. Since HTTP/1.1, connections are persistent by default and reused for many requests. The protocol is still stateless.
VersionYearTransportWhat changed
HTTP/1.01996TCPNew connection for each request by default
HTTP/1.11997 (current spec 2022)TCPPersistent connections, mandatory Host header, text format
HTTP/22015TCPBinary framing, many requests multiplexed on one connection, header compression
HTTP/32022QUIC over UDPFaster setup, no TCP head-of-line blocking, encryption built in

HTTPS is HTTP sent through an encrypted TLS channel on port 443. Use TLS 1.3 (or 1.2); SSL and TLS 1.0/1.1 are deprecated and should be disabled.

HTTP methods

  • GET: retrieve information.
  • POST: send data to the server for processing (create a resource, submit a form).
  • PUT: replace a resource with the one sent.
  • PATCH: partially modify a resource.
  • DELETE: remove a resource.
  • HEAD: like GET but return the headers only.
  • OPTIONS: ask which methods the server supports.
  • TRACE: echo the request back (diagnostics; usually disabled on public servers for security).

Method safety and idempotence

Safe
The method only reads; it is not meant to change anything on the server.
Idempotent
Sending the same request once or ten times leaves the server in the same final state. Every safe method is also idempotent.
HTTP methodSafeIdempotent
OPTIONSYesYes
GETYesYes
HEADYesYes
PUTNoYes
POSTNoNo
DELETENoYes
TRACEYesYes
PATCHNoNo (not guaranteed)
Example

PUT /users/7 {"name":"Sara"} sent twice: user 7 is still named Sara, so PUT is idempotent. POST /orders sent twice: two orders are created, so POST is not. This is why browsers warn you before re-submitting a form.

Common mistake

Thinking DELETE is not idempotent because the second call returns 404. Idempotence is about the server's state, not the response code: after one or two DELETEs the resource is gone either way.

FTP

FTP (File Transfer Protocol) transfers files between computers, classically from your computer to a web server. It uses two TCP connections: port 21 for the control connection (commands such as USER, RETR, STOR) and a separate data connection, which comes from port 20 in active mode. In passive mode, which most clients use today because it works through firewalls and NAT, the client connects to a random high port that the server announces.

Updated

Plain FTP sends usernames and passwords unencrypted. Use SFTP (file transfer over SSH, port 22) or FTPS (FTP over TLS) instead. Modern browsers no longer support ftp:// links.

5Middleware & Advanced Distribution

What is middleware?

Middleware is connectivity software that lets multiple processes on different machines interact across a network. It sits between the application and the operating system and network, hiding sockets, data formats and platform differences. It was essential for migrating mainframe applications to client/server, and it still provides communication across heterogeneous platforms.

Analogy

A professional interpreter and courier in one. Two people who speak different languages and live in different cities can still do business, because the middle person handles translation and delivery.

Middleware types

TypeIdeaExamples
RPC (Remote Procedure Call)Call a function on another machine as if it were local; usually synchronousONC RPC, gRPC
MOM (Message-Oriented Middleware)Send messages to a queue; the receiver processes them later (asynchronous)RabbitMQ, IBM MQ, Jakarta Messaging (JMS)
Publish/SubscribePublishers send to a topic; every subscriber of that topic receives a copyApache Kafka, MQTT
ORB (Object Request Broker)Call methods on remote objects across languagesCORBA (legacy)
SQL-oriented data accessA standard API for talking to any databaseODBC, JDBC, ADO.NET

Database middleware

  • ODBC (Open Database Connectivity): a language-independent C API for databases; still widely used.
  • OLE DB: Microsoft's COM-based enhancement of ODBC for Windows. It is still supported for SQL Server, but new .NET code uses ADO.NET.
  • JDBC (Java Database Connectivity): the standard Java API for relational databases.

JDBC architecture

Java application→JDBC API→DriverManager / DataSource→JDBC driver→Database

Your code uses only the standard interfaces (Connection, Statement, ResultSet). The driver for MySQL, PostgreSQL or Oracle does the database-specific work, so you can switch databases by changing the driver and the URL. Real applications usually get connections from a DataSource with a connection pool instead of DriverManager.

JDBCExample.java (updated driver name)

// JDBC Connection Example
import java.sql.*;

public class JDBCExample {
    // Updated: "com.mysql.jdbc.Driver" is the old, deprecated name.
    // MySQL Connector/J 8 and later use "com.mysql.cj.jdbc.Driver".
    static final String JDBC_DRIVER = "com.mysql.cj.jdbc.Driver";
    static final String DB_URL = "jdbc:mysql://localhost/EMP";
    static final String USER = "username";
    static final String PASS = "password";

    public static void main(String[] args) {
        Connection conn = null;
        Statement stmt = null;
        try {
            // Register JDBC driver (optional since JDBC 4.0 / Java 6:
            // drivers on the classpath register themselves)
            Class.forName(JDBC_DRIVER);

            // Open a connection
            conn = DriverManager.getConnection(DB_URL, USER, PASS);

            // Execute a query
            stmt = conn.createStatement();
            String sql = "SELECT id, first, last, age FROM Employees";
            ResultSet rs = stmt.executeQuery(sql);

            // Extract data from result set
            while(rs.next()) {
                int id = rs.getInt("id");
                int age = rs.getInt("age");
                String first = rs.getString("first");
                String last = rs.getString("last");

                System.out.print("ID: " + id);
                System.out.print(", Age: " + age);
                System.out.print(", First: " + first);
                System.out.println(", Last: " + last);
            }
            rs.close();
            stmt.close();
            conn.close();
        } catch(SQLException se) {
            se.printStackTrace();
        } catch(Exception e) {
            e.printStackTrace();
        }
    }
}
Show the modern version (try-with-resources) 
import java.sql.*;

public class JDBCExampleModern {
    public static void main(String[] args) {
        String url = "jdbc:mysql://localhost/EMP";
        String sql = "SELECT id, first, last, age FROM Employees";
        // Resources declared here are closed automatically, even on errors
        try (Connection conn = DriverManager.getConnection(url, "username", "password");
             Statement stmt = conn.createStatement();
             ResultSet rs = stmt.executeQuery(sql)) {
            while (rs.next()) {
                System.out.println("ID: " + rs.getInt("id") + ", Age: " + rs.getInt("age")
                    + ", First: " + rs.getString("first") + ", Last: " + rs.getString("last"));
            }
        } catch (SQLException e) {
            e.printStackTrace();
        }
    }
}

No Class.forName and no manual close() calls. If an exception happens half-way, the connection is still closed, which the original version does not guarantee.

Common mistake

Building SQL by joining strings with user input ("... WHERE name='" + name + "'"). That allows SQL injection. Use a PreparedStatement with ? placeholders; the Extended Edition shows how.

6Remote Invocation (RPC & RMI)

RPC: Remote Procedure Call

A mechanism to execute subroutines on other hosts without writing socket code in your program. The network code is hidden inside generated stub procedures.

RMI: Remote Method Invocation

Java's object-oriented RPC: an object in one JVM invokes methods on an object running in another JVM. Used to build distributed Java applications.

CORBA

Common Object Request Broker Architecture: a platform- and language-independent framework for distributed objects. Now legacy; removed from the JDK in Java 11.

The RPC mechanism

Client→Client stub→Network→Server stub→Server procedure

Then the same path in reverse carries the result back.

  1. The client calls the client stub exactly like a local function.
  2. The stub marshals the parameters: marshalling packs them into a message.
  3. The message crosses the network to the server machine.
  4. The server stub unmarshals the parameters and calls the real procedure.
  5. The result returns through the server stub, the network and the client stub, back to the caller.
Analogy

Ordering by phone. You tell the shop assistant what you want; they write it on an order form (marshalling), fax it to the warehouse, where someone reads the form (unmarshalling) and fills the order. You never deal with the fax machine.

An RMI remote interface

// RMI Remote Interface Example
import java.rmi.Remote;
import java.rmi.RemoteException;

public interface Calculator extends Remote {
    public long add(long a, long b) throws RemoteException;
    public long sub(long a, long b) throws RemoteException;
    public long mul(long a, long b) throws RemoteException;
    public long div(long a, long b) throws RemoteException;
}

Two rules make an interface remote: it extends java.rmi.Remote, and every method declares RemoteException, because any remote call can fail for network reasons. The server registers an implementation in the RMI registry (port 1099 by default), and the client looks it up by name to get a stub.

RPC (classic)Java RMICORBAgRPC (modern)
CallsProceduresMethods on objectsMethods on objectsService methods
LanguagesMostly CJava onlyMany (via IDL)Many (via .proto files)
Wire formatXDRJava serializationIIOPProtocol Buffers over HTTP/2

Common mistake

Believing a remote call behaves exactly like a local one. It is slower by orders of magnitude, it can fail half-way, and parameters are copied, not shared. That is why RemoteException is a checked exception.

Exam tip

"Difference between RPC and RMI?" RPC calls procedures and passes plain data; RMI is object-oriented, Java-only, can pass whole objects (serialized) and remote references, and uses a registry to find objects by name.

8Check your understanding

Quiz: the whole overview

Q1In the client/server model, which side starts the conversation?

The client initiates; the server waits (listens) and responds. If both sides could start conversations as equals, that would be peer-to-peer.

Q2True or false: a server must be a powerful, dedicated machine.

False. "Server" is a role played by a program. A laptop, a Raspberry Pi or a container can run a server; powerful hardware is only needed for heavy load.

Q3In a 3-tier architecture, where does the business logic live?

3-tier separates presentation (client), logic (application server) and data (database server). Moving logic off the client is what makes 3-tier easier to manage and reuse.

Q4Why does 2-tier usually perform worse than 3-tier over a network?

In 2-tier, every query travels between client and database. In 3-tier the client makes one request and the many queries run between application server and database, which are close together.

Q5What is the size of a UDP header?

UDP's header has only four 2-byte fields (source port, destination port, length, checksum) = 8 bytes. 20–60 bytes is TCP's header.

Q6Which transport does HTTP/3 use?

HTTP/3 runs on QUIC, which is built on UDP and adds its own reliability and TLS 1.3 encryption. This avoids TCP head-of-line blocking. HTTP/1.1 and HTTP/2 use TCP.

Q7Which HTTP method is neither safe nor idempotent?

Sending the same POST twice usually creates two resources (two orders), so it is not idempotent. PUT and DELETE are idempotent but not safe; GET is both.

Q8Today, HTTP is best described as:

The protocol itself remembers nothing between requests (stateless). The "connectionless" label is from HTTP/1.0; HTTP/1.1 keeps connections open by default. Cookies add state at the application level.

Q9On which port does FTP's control connection run?

Port 21 carries commands. Port 20 is the data connection in active mode. Port 22 is SSH, which also carries SFTP, the secure replacement for FTP.

Q10What is the main job of middleware?

Middleware sits between applications and the OS/network: RPC, message queues, ORBs and database APIs like JDBC are all middleware.

Q11In RPC, what does the client stub do?

The client stub is a local stand-in. It packs (marshals) the arguments, sends the request, waits, and unpacks the reply. The real procedure runs on the server.

Q12In modern JDBC (4.0 and later), is Class.forName("com.mysql.cj.jdbc.Driver") required?

Since JDBC 4.0 (Java 6), DriverManager finds drivers automatically through the service-provider mechanism. The line is harmless but optional. The class name also changed: com.mysql.jdbc.Driver is the old, deprecated one.

Summary

  • Client/server: clients initiate requests, servers listen and respond, using a shared protocol over IPC. Roles, not hardware.
  • Pros: central management, scalability, data sharing, security. Cons: cost, complex setup, single point of failure, congestion.
  • 2-tier puts logic on the client; 3-tier moves it to an application server for better performance, scalability and reuse; N-tier adds specialised components.
  • Sockets = IP address + port. TCP is reliable and ordered (20–60 byte header); UDP is fast and connectionless (8 byte header) and now also carries HTTP/3 via QUIC.
  • HTTP is stateless and media independent; HTTP/1.1 keeps connections open, HTTP/2 multiplexes, HTTP/3 uses QUIC. Use HTTPS with TLS 1.2 or 1.3.
  • Safe methods only read (GET, HEAD, OPTIONS, TRACE); idempotent methods can be repeated safely (those plus PUT and DELETE). POST and PATCH are neither.
  • Middleware hides the network: RPC, MOM, publish/subscribe, ORBs and database APIs (ODBC, JDBC). JDBC = API + driver; prefer try-with-resources and PreparedStatement.
  • RPC hides network code in stubs that marshal parameters; RMI is Java's object version with a registry on port 1099; CORBA is legacy; gRPC is today's common choice.
