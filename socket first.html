Java Network Programming

How a Java program finds another computer (InetAddress) and talks to it (sockets over TCP and UDP). Every web browser, chat app, game and database driver is built on these ideas, so this is the foundation for everything that follows in the course.

1Why network programming?

Network programming means writing programs that exchange data with other programs over a network. Modern applications almost never run alone: from web browsers to chat applications, from file transfer to online gaming, network programming is the backbone of distributed systems.

Java's networking API lives in the java.net package (plus java.net.http since Java 11). This guide focuses on two key components:

InetAddress class

Java's representation of an IP address. Used to resolve hostnames to IP addresses and vice versa.

Socket programming

Lets a client and a server exchange data over a network using the TCP or UDP protocol.

Key concepts we will cover

Host
Any device connected to a network: a laptop, a phone, a server, a printer.
IP address
A unique identifier for a host on a network. IPv4 uses 32 bits (192.168.1.10); IPv6 uses 128 bits (2001:db8::1).
Hostname resolution
Converting a domain name such as google.com into an IP address, done by DNS.
Port
A 16-bit number (0–65535) that identifies one application or service on a host, the endpoint for communication on a device.
Protocol
An agreed set of rules for exchanging messages. At the transport layer, the two you use from Java are TCP and UDP.
Client-server model
The foundation of networked applications: a server waits for requests; a client starts the conversation.
Analogy

Think of the network as a city. The IP address is the street address of a building (the host), the port is the apartment number inside it (the application), and DNS is the directory that turns a business name into a street address.

2The InetAddress class

The java.net.InetAddress class represents an Internet Protocol (IP) address. It is used to perform hostname resolution (name to IP) and reverse lookup (IP to name). It has two subclasses, Inet4Address and Inet6Address, so the same code works for IPv4 and IPv6.

Creating InetAddress instances

InetAddress has no public constructor, so you must obtain instances through static factory methods. This lets Java check the input, use its DNS cache, and return the right subclass for IPv4 or IPv6. Instances are immutable (they cannot change after creation), which makes them safe to share between threads.

InetAddressDemo.java

import java.net.InetAddress;
import java.net.UnknownHostException;

public class InetAddressDemo {
    public static void main(String[] args) {
        try {
            // Get local host address
            InetAddress localHost = InetAddress.getLocalHost();
            System.out.println("Local Host: " + localHost);

            // Get address by hostname (DNS lookup)
            InetAddress google = InetAddress.getByName("google.com");
            System.out.println("Google: " + google);

            // Get all addresses for a hostname (IPv4 and IPv6)
            InetAddress[] allGoogle = InetAddress.getAllByName("www.google.com");
            System.out.println("All Google addresses:");
            for (InetAddress addr : allGoogle) {
                System.out.println("  - " + addr);
            }

            // Get address from an IP string: no DNS lookup is done here
            InetAddress fromIP = InetAddress.getByName("8.8.8.8");
            System.out.println("From IP: " + fromIP);
            // getHostName() now does a reverse DNS lookup
            System.out.println("Host Name: " + fromIP.getHostName());
            System.out.println("IP string: " + fromIP.getHostAddress());
        } catch (UnknownHostException e) {
            System.err.println("Error: could not resolve hostname: " + e.getMessage());
        }
    }
}

Reachable.java

import java.io.IOException;
import java.net.InetAddress;

public class Reachable {
    public static void main(String[] args) throws IOException {
        InetAddress local = InetAddress.getLocalHost();
        System.out.println("Host Name: " + local.getHostName());
        System.out.println("IP Address: " + local.getHostAddress());
        // isReachable throws IOException; may need admin rights to send real pings
        System.out.println("Is reachable: " + local.isReachable(5000));
    }
}
Common mistake

Forgetting that every lookup can fail. getByName, getAllByName and getLocalHost throw the checked exception UnknownHostException, so the code does not compile unless you catch it or declare it.

Exam tip

"Why does InetAddress have no constructor?" Answer: it uses static factory methods so it can validate input, reuse cached DNS results and return the correct subclass (Inet4Address or Inet6Address). This is the factory method design pattern.

3Socket basics

A socket is one endpoint of a two-way communication link between two programs running on the network. Sockets provide the communication mechanism between two computers: your program writes bytes into its socket, and they come out of the socket at the other end.

The client-server communication model

Client socket⇄Network⇄Server socket
  • Client: creates a socket and attempts to connect to a server (for example, a web browser connecting to a website).
  • Server: listens for connections on a known port and creates a separate socket for each client (for example, a web server waiting for requests).
  • Socket address: IP address + port number, written 192.168.1.10:8080.

Socket addressing

Every socket is identified by a combination of:

  • IP address: identifies the host (e.g. 192.168.1.10).
  • Port number: identifies the application or service (e.g. 80 for HTTP).

A whole TCP connection is identified by four values, the four-tuple: client IP, client port, server IP, server port. That is why one web server on port 443 can hold thousands of connections at once: each client has a different IP or port, so every tuple is unique.

Example

Two browser tabs on your laptop open https://example.com. The connections are 192.168.1.23:51544 → 93.184.215.14:443 and 192.168.1.23:51545 → 93.184.215.14:443. Same server port, different client ports, so the server keeps them apart.

TCP vs UDP sockets

TCP (Transmission Control Protocol) and UDP (User Datagram Protocol) are the two transport protocols you use from Java.

Analogy

TCP is a phone call: you dial first, the other side answers, and words arrive in order; if you miss something you ask again. UDP is sending postcards: each card travels on its own, cheaply, but some may get lost or arrive in a different order.

Common mistake

Saying "the web always uses TCP". HTTP/1.1 and HTTP/2 run over TCP, but HTTP/3 runs over QUIC, which is built on UDP and adds its own reliability and encryption. Also, DNS uses UDP for normal queries but falls back to TCP for large responses.

4How a TCP connection works

Before a TCP client and server can exchange data, their operating systems perform the three-way handshake. In Java this happens inside new Socket(host, port) on the client and accept() on the server; you never send SYN or ACK yourself.

TCP connection lifecycle in Java

  1. Server creates a ServerSocket and binds it to a port (e.g. 12345).
  2. Server calls accept() and waits (blocks) for client connections.
  3. Client creates a Socket and connects to the server; the operating systems perform the handshake.
  4. Connection established: accept() returns a new Socket for this client, and data exchange begins.
  5. Communication happens through the socket's InputStream and OutputStream, usually wrapped in readers and writers.
  6. Connection closed by either party with close(). When one side closes, the other side's readLine() returns null.
Key idea

A ServerSocket never carries data. It only waits for connections. Each call to accept() returns a brand-new Socket that is used to talk to that one client.

Analogy

The ServerSocket is a company's receptionist. When a caller arrives, the receptionist hands them to an employee (a new Socket) and goes back to waiting at the desk for the next caller.

5TCP socket programming in Java

Java provides two key classes for TCP socket programming:

  • java.net.Socket: for client-side communication (and for the server's per-client connection).
  • java.net.ServerSocket: for server-side listening and accepting connections.

Sockets give you raw byte streams. To send text lines, wrap them: BufferedReader over an InputStreamReader to read lines, and PrintWriter to write lines. Always name the character set (StandardCharsets.UTF_8); otherwise Java before version 18 uses the platform default and the two sides may disagree about accented or Arabic characters.

Simple TCP server and client (one message)

These are the smallest possible pair: the server accepts one client, reads one line, answers, and exits. They use try-with-resources so every socket and stream is closed automatically.

SimpleTCPServer.java

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.ServerSocket;
import java.net.Socket;
import java.nio.charset.StandardCharsets;

public class SimpleTCPServer {
    public static void main(String[] args) throws IOException {
        // Create server socket listening on port 12345
        try (ServerSocket serverSocket = new ServerSocket(12345)) {
            System.out.println("Server started. Waiting for client...");

            // Wait for a client connection, then create input and output streams
            try (Socket clientSocket = serverSocket.accept();
                 BufferedReader in = new BufferedReader(new InputStreamReader(
                         clientSocket.getInputStream(), StandardCharsets.UTF_8));
                 PrintWriter out = new PrintWriter(
                         clientSocket.getOutputStream(), true, StandardCharsets.UTF_8)) {

                System.out.println("Client connected: " + clientSocket.getInetAddress());

                String message = in.readLine();          // read client message
                System.out.println("Received: " + message);
                out.println("Echo: " + message);         // send response (auto-flushed)
            } // client socket and streams closed here
        }     // server socket closed here
    }
}

SimpleTCPClient.java

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.Socket;
import java.nio.charset.StandardCharsets;

public class SimpleTCPClient {
    public static void main(String[] args) throws IOException {
        // Connect to server on localhost, port 12345, and create streams
        try (Socket socket = new Socket("localhost", 12345);
             PrintWriter out = new PrintWriter(socket.getOutputStream(), true, StandardCharsets.UTF_8);
             BufferedReader in = new BufferedReader(new InputStreamReader(
                     socket.getInputStream(), StandardCharsets.UTF_8))) {

            out.println("Hello Server!");                 // send message to server
            String response = in.readLine();               // read server response
            System.out.println("Server response: " + response);
        }
    }
}
Common mistake

Forgetting to flush. Writers keep data in a buffer; if it is never flushed, the other side waits forever. new PrintWriter(stream, true, ...) turns on auto-flush for println; otherwise call out.flush(). Also remember that readLine() waits for a newline, so send lines with println, not print.

Complete runnable TCP echo pair

This version is closer to a real server: it loops forever, handles many clients at the same time (one thread per client), echoes every line until the client types bye, and uses timeouts so a silent client cannot block a thread forever.

EchoServer.java

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.ServerSocket;
import java.net.Socket;
import java.net.SocketTimeoutException;
import java.nio.charset.StandardCharsets;

public class EchoServer {
    public static void main(String[] args) throws IOException {
        int port = args.length > 0 ? Integer.parseInt(args[0]) : 5000;
        try (ServerSocket server = new ServerSocket(port)) {
            System.out.println("Echo server listening on port " + port);
            while (true) {
                Socket client = server.accept();            // blocks until a client connects
                new Thread(() -> handle(client)).start();   // serve it on its own thread
            }
        }
    }

    private static void handle(Socket client) {
        String who = client.getRemoteSocketAddress().toString();
        System.out.println("Connected: " + who);
        try (client;   // Java 9+: close this existing socket at the end
             BufferedReader in = new BufferedReader(new InputStreamReader(
                     client.getInputStream(), StandardCharsets.UTF_8));
             PrintWriter out = new PrintWriter(client.getOutputStream(), true, StandardCharsets.UTF_8)) {

            client.setSoTimeout(60_000);                    // drop clients idle for 60 s
            String line;
            while ((line = in.readLine()) != null) {        // null = client closed the connection
                if (line.equalsIgnoreCase("bye")) {
                    out.println("Goodbye");
                    break;
                }
                out.println("Echo: " + line);
            }
        } catch (SocketTimeoutException e) {
            System.out.println("Idle timeout: " + who);
        } catch (IOException e) {
            System.err.println("Error with " + who + ": " + e.getMessage());
        }
        System.out.println("Disconnected: " + who);
    }
}

EchoClient.java

import java.io.BufferedReader;
import java.io.IOException;
import java.io.InputStreamReader;
import java.io.PrintWriter;
import java.net.ConnectException;
import java.net.InetSocketAddress;
import java.net.Socket;
import java.net.SocketTimeoutException;
import java.net.UnknownHostException;
import java.nio.charset.StandardCharsets;

public class EchoClient {
    public static void main(String[] args) {
        String host = args.length > 0 ? args[0] : "localhost";
        int port = args.length > 1 ? Integer.parseInt(args[1]) : 5000;

        try (Socket socket = new Socket()) {
            socket.connect(new InetSocketAddress(host, port), 5_000); // connect timeout: 5 s
            socket.setSoTimeout(10_000);                               // read timeout: 10 s

            try (BufferedReader in = new BufferedReader(new InputStreamReader(
                         socket.getInputStream(), StandardCharsets.UTF_8));
                 PrintWriter out = new PrintWriter(socket.getOutputStream(), true, StandardCharsets.UTF_8);
                 BufferedReader keyboard = new BufferedReader(new InputStreamReader(
                         System.in, StandardCharsets.UTF_8))) {

                System.out.println("Connected to " + socket.getRemoteSocketAddress()
                        + ". Type a line and press Enter; type bye to quit.");
                String line;
                while ((line = keyboard.readLine()) != null) {
                    out.println(line);
                    String reply = in.readLine();
                    if (reply == null) {                // server closed the connection
                        break;
                    }
                    System.out.println(reply);
                    if (line.equalsIgnoreCase("bye")) {
                        break;
                    }
                }
            }
        } catch (UnknownHostException e) {
            System.err.println("Unknown host: " + host);
        } catch (ConnectException e) {
            System.err.println("Connection refused: is the server running on port " + port + "?");
        } catch (SocketTimeoutException e) {
            System.err.println("Timed out: " + e.getMessage());
        } catch (IOException e) {
            System.err.println("I/O error: " + e.getMessage());
        }
    }
}

How to run it

  1. Save both files in one folder and compile: javac EchoServer.java EchoClient.java
  2. In terminal 1 start the server: java EchoServer (optionally java EchoServer 6000 for another port).
  3. In terminal 2 start a client: java EchoClient (or java EchoClient 192.168.1.20 5000 for a server on another machine).
  4. Type lines; each comes back as Echo: .... Open a third terminal with another client to see two clients served at once. Type bye to finish.
Tip

If the client says "Connection refused", the server is not running, is on another port, or a firewall blocks it. If the server says "Address already in use" (BindException), another program, or an old copy of your server, already holds the port.

6Serving many clients

accept() and readLine() are blocking calls. A server with one thread can therefore talk to only one client at a time: while it waits for client A to type, client B is stuck. There are three standard solutions:

ApproachHow it worksWhen to use
Thread per clientnew Thread(...) for each accepted socket (the EchoServer above)Simple programs and labs; platform threads are expensive, so it does not scale to many thousands
Thread poolExecutors.newFixedThreadPool(n) reuses a fixed number of threadsCaps resource use; extra clients wait in a queue
Virtual threads (Java 21)Executors.newVirtualThreadPerTaskExecutor(): very cheap threads managed by the JVMKeeps the simple blocking style while serving tens of thousands of connections
NIO (non-blocking I/O)java.nio.channels.Selector lets one thread watch many channelsHigh-performance frameworks (e.g. Netty); more complex code

Accept loop with virtual threads (Java 21+), reusing handle() from EchoServer

// In EchoServer.java add these imports:
//   import java.util.concurrent.ExecutorService;
//   import java.util.concurrent.Executors;
// then replace main() with this version:
public static void main(String[] args) throws IOException {
    try (ServerSocket server = new ServerSocket(5000);
         ExecutorService pool = Executors.newVirtualThreadPerTaskExecutor()) {
        while (true) {
            Socket client = server.accept();
            pool.submit(() -> handle(client));   // one cheap virtual thread per client
        }
    }
}
Exam tip

"Why does a TCP server need multithreading?" Because accept() and read() block. Without extra threads (or non-blocking I/O) the server serves one client at a time, and a slow client blocks everyone else.

7UDP sockets in Java

With UDP there is no connection and no stream. You put bytes into a DatagramPacket (a message plus the destination address and port) and send it through a DatagramSocket. The receiver gets whole packets, one at a time, or nothing at all if a packet is lost.

DatagramSocket
The UDP endpoint. Use new DatagramSocket(port) on a server and new DatagramSocket() (any free port) on a client.
DatagramPacket
One message: a byte array, its length and (for sending) the target address. receive() fills a packet and tells you who sent it.

UdpEchoServer.java

import java.io.IOException;
import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.nio.charset.StandardCharsets;

public class UdpEchoServer {
    public static void main(String[] args) throws IOException {
        try (DatagramSocket socket = new DatagramSocket(5001)) {
            System.out.println("UDP echo server on port 5001");
            byte[] buf = new byte[1024];
            while (true) {
                DatagramPacket request = new DatagramPacket(buf, buf.length);
                socket.receive(request);                       // blocks until a datagram arrives
                String text = new String(request.getData(), 0, request.getLength(),
                                         StandardCharsets.UTF_8);
                System.out.println("From " + request.getSocketAddress() + ": " + text);

                byte[] reply = ("Echo: " + text).getBytes(StandardCharsets.UTF_8);
                socket.send(new DatagramPacket(reply, reply.length, request.getSocketAddress()));
            }
        }
    }
}

UdpEchoClient.java

import java.io.IOException;
import java.net.DatagramPacket;
import java.net.DatagramSocket;
import java.net.InetAddress;
import java.net.SocketTimeoutException;
import java.nio.charset.StandardCharsets;

public class UdpEchoClient {
    public static void main(String[] args) throws IOException {
        InetAddress server = InetAddress.getByName(args.length > 0 ? args[0] : "localhost");
        try (DatagramSocket socket = new DatagramSocket()) {  // OS picks an ephemeral port
            socket.setSoTimeout(2_000);                         // do not wait forever for a reply

            byte[] data = "Hello over UDP".getBytes(StandardCharsets.UTF_8);
            socket.send(new DatagramPacket(data, data.length, server, 5001));

            byte[] buf = new byte[1024];
            DatagramPacket reply = new DatagramPacket(buf, buf.length);
            try {
                socket.receive(reply);
                System.out.println(new String(reply.getData(), 0, reply.getLength(),
                                              StandardCharsets.UTF_8));
            } catch (SocketTimeoutException e) {
                System.out.println("No reply within 2 s: the request or the reply may have been lost.");
            }
        }
    }
}
Common mistake

Using new String(packet.getData()) without the length. The buffer is 1024 bytes but the message may be 14, so you would print the message followed by leftover bytes. Always use getLength(). Also keep UDP messages small (well under about 1,400 bytes) so they are not fragmented.

Key idea

With UDP, reliability is your job. If you need it, add timeouts, retries, and sequence numbers yourself, or use a protocol such as QUIC that already does this on top of UDP.

8Exceptions and timeouts

Network operations can fail in many ways: the name does not exist, the server is down, a cable is unplugged, or the other side is simply slow. Always handle these common exceptions:

ExceptionMeaningTypical cause
UnknownHostExceptionHost cannot be resolved to an IP addressTypo in hostname, no DNS, no internet
ConnectExceptionConnection refusedNothing is listening on that port, or a firewall rejected it
SocketTimeoutExceptionConnect or read timeout expiredServer too slow, packets dropped, UDP reply lost
BindExceptionCannot bind the server portPort already in use, or a privileged port without rights
SocketExceptionGeneral socket error"Connection reset": the other side closed abruptly
IOExceptionGeneral I/O error; parent of all the aboveCatch it last

The hierarchy matters because Java requires more specific exceptions to be caught before their parents: ConnectException and BindException extend SocketException; SocketTimeoutException extends InterruptedIOException; all of them, and UnknownHostException, extend IOException.

Two different timeouts

Socket socket = new Socket();
socket.connect(new InetSocketAddress("example.com", 80), 5_000); // connect timeout
socket.setSoTimeout(5_000); // read timeout: each read() waits at most 5 s
Common mistake

Believing setSoTimeout() limits how long connecting takes. It only limits each read. new Socket(host, port) has no connect timeout of its own; use connect(address, timeout) on an unconnected socket as above. Without timeouts, a client can hang indefinitely.

Tip

Give users helpful messages ("Cannot reach the server, check your connection") instead of stack traces, and consider retrying with a delay for temporary failures.

9Beyond raw sockets: URLs and HttpClient

Sockets are the foundation, but for web protocols you normally use a higher-level API that speaks HTTP for you. Since Java 11, java.net.http.HttpClient is the standard choice; it supports HTTP/1.1 and HTTP/2, TLS, timeouts and asynchronous calls.

HttpDemo.java

import java.io.IOException;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.time.Duration;

public class HttpDemo {
    public static void main(String[] args) throws IOException, InterruptedException {
        HttpClient client = HttpClient.newBuilder()
                .connectTimeout(Duration.ofSeconds(5))
                .build();
        HttpRequest request = HttpRequest.newBuilder(URI.create("https://example.com/"))
                .timeout(Duration.ofSeconds(10))
                .GET()
                .build();
        HttpResponse<String> response = client.send(request, HttpResponse.BodyHandlers.ofString());
        System.out.println("Status: " + response.statusCode() + ", version: " + response.version());
        System.out.println("Body length: " + response.body().length() + " characters");
    }
}
Outdated code to avoid

The constructor new URL(String) is deprecated since Java 20. Write URI.create("https://example.com/").toURL() instead (it still throws MalformedURLException, a subclass of IOException). Prefer HttpClient over the old HttpURLConnection in new code.

Quiz: InetAddress and sockets

Q1Which method would you use to get ALL IP addresses associated with "google.com"?

getAllByName returns an array with every address DNS gives for the name. getByName returns only one of them; getHostAddress just formats an address you already have.

Q2What is the main difference between TCP and UDP?

TCP sets up a connection and guarantees ordered delivery. UDP sends independent datagrams without guarantees, which makes it lighter and lower-latency. The last option has the two swapped: TCP is a stream, UDP uses datagrams.

Q3Which port range is typically used for ephemeral (temporary client) ports?

IANA reserves 49152–65535 as the dynamic/private (ephemeral) range. 0–1023 are well-known ports and 1024–49151 are registered ports. (Some operating systems use a different range, such as 32768–60999 on Linux.)

Q4What exception is thrown when a hostname cannot be resolved?

UnknownHostException (a subclass of IOException) signals that DNS could not find an address. NetworkException does not exist in java.net.

Q5In TCP socket programming, which class is used on the server side to listen for incoming connections?

ServerSocket binds to a port and its accept() method waits for clients. Socket is a single connection; DatagramSocket is for UDP; InetSocketAddress only holds an IP and port.

Q6What does serverSocket.accept() do?

accept() blocks (waits) and returns a new Socket per client. The handshake itself is done by the operating system; the ServerSocket keeps listening for the next client.

Q7What is the correct order of the TCP three-way handshake?

The client sends SYN, the server answers SYN-ACK, and the client confirms with ACK. FIN is used to close a connection, not to open one.

Q8Why do video calls and online games usually prefer UDP?

TCP would pause the whole stream to retransmit a lost segment. For real-time media, a small glitch is better than a delay, so UDP's low latency wins.

Q9What does socket.setSoTimeout(5000) control?

SO_TIMEOUT is a read timeout. For a connect timeout use socket.connect(new InetSocketAddress(host, port), ms).

Q10True or false: InetAddress.getByName("8.8.8.8") sends a DNS query.

When given an IP literal, getByName only checks its format and builds the object. A DNS (reverse) lookup happens later, only if you call getHostName().

Q11Which pair of classes is used for UDP in Java?

DatagramSocket sends and receives; DatagramPacket holds one message and its address. Socket and ServerSocket are TCP; UdpSocket does not exist.

Q12True or false: TCP keeps message boundaries, so two write() calls always arrive as two separate read() results.

TCP is a byte stream. Two writes may arrive in one read, or one write may be split across several reads. That is why we use a delimiter such as newline (readLine) or a length prefix. UDP, in contrast, keeps datagram boundaries.

Q13A client gets ConnectException: Connection refused. What is the most likely cause?

"Refused" means the host answered with a reset because nothing listens on the port (or a firewall rejects it). A misspelled name gives UnknownHostException; slowness gives SocketTimeoutException.

Q14Why create new PrintWriter(socket.getOutputStream(), true, StandardCharsets.UTF_8) with true?

The second argument is autoFlush. Without flushing, text can sit in the buffer and the other side waits forever, a classic socket bug.

Q15Which Java 21 feature lets a simple "one thread per client" server handle tens of thousands of connections?

Virtual threads are lightweight threads scheduled by the JVM, so blocking in accept() or readLine() costs very little. You keep simple blocking code while scaling much further than platform threads.

Q16In current Java, how should you create a URL object from a string?

The URL(String) constructors are deprecated since Java 20 because they do not validate well. Build a URI first, then call toURL(). InetAddress takes a hostname, not a URL.

import java.net.Inet6Address;
import java.net.InetAddress;
import java.net.UnknownHostException;

public class ListAddresses {
    public static void main(String[] args) {
        if (args.length != 1) {
            System.err.println("Usage: java ListAddresses <hostname>");
            return;
        }
        try {
            for (InetAddress a : InetAddress.getAllByName(args[0])) {
                String kind = (a instanceof Inet6Address) ? "IPv6" : "IPv4";
                System.out.println(kind + "  " + a.getHostAddress());
            }
        } catch (UnknownHostException e) {
            System.err.println("Cannot resolve " + args[0]);
        }
    }
}

Summary

  • InetAddress represents an IPv4 or IPv6 address; create it with factory methods (getByName, getAllByName, getLocalHost) and handle UnknownHostException.
  • A socket is one endpoint of a connection: IP address + port. A TCP connection is identified by the four-tuple of both endpoints.
  • Ports: 0–1023 well-known, 1024–49151 registered, 49152–65535 dynamic (ephemeral).
  • TCP: connection-oriented, reliable, ordered byte stream (Socket, ServerSocket). UDP: connectionless, unreliable datagrams with low overhead (DatagramSocket, DatagramPacket).
  • The server's accept() blocks and returns a new Socket per client; use threads, a pool, virtual threads (Java 21) or NIO to serve many clients.
  • Use try-with-resources, name the charset (StandardCharsets.UTF_8), flush output, and set both connect and read timeouts.
  • For HTTP use java.net.http.HttpClient; avoid the deprecated new URL(String).
