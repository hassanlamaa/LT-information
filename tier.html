1Quick recap

A tier is a part of a client/server system that can run on its own, usually on its own machine, and talks to the other parts over a network. We can combine or separate the presentation, business logic and data into different tiers to balance simplicity, scalability and security.

Presentation
The user interface: screens, forms, buttons.
Business logic
The rules: validation, calculations, decisions ("orders over $50 ship free").
Data
Permanent storage, usually a database.
Layer vs tier
A layer is a logical grouping of code; a tier is where that code is physically deployed. Several layers can share one tier.
Rule of thumb

More tiers = more flexibility and scalability, but also more complexity, more cost and a little more latency per request.

  • 1-tier: everything in one program on one machine. Example: a spreadsheet or an offline desktop app with a local SQLite file.
  • 2-tier: a thick client (UI + logic) connects directly to a database server. Example: a desktop app on office PCs querying a shared SQL Server.
  • 3-tier: presentation → application server → database. The client never touches the database. Example: almost every web application.
  • N-tier: more than three tiers, such as load balancer, web tier, API gateway, separate services, cache, message queue and database. Example: large cloud and microservice systems.
Analogy

A restaurant: the waiter and dining room are the presentation tier, the kitchen is the application tier, the storeroom is the data tier. Customers never walk into the storeroom; they ask the waiter. That is exactly why 3-tier is more secure than 2-tier.

Exam tip

If a question asks "where does the business logic live?", the expected answers are: 1-tier, in the single program; 2-tier, in the client; 3-tier, on the application server; N-tier, spread over several service tiers.

Common mistake

A website is not 2-tier just because there is "a browser and a server". The browser talks to an application server, which talks to the database: three tiers.

Part A: Tier basics

Q1Which tier type usually combines UI, logic and data in one application?

1-tier puts all three layers in a single program on one machine. Every other model splits them across machines.

Q2Which statement is true?

Extra tiers let you scale and change parts independently, but you have more components to deploy, secure and monitor. 1-tier is the least scalable, and 2-tier's second tier is the database.

Q3What is the best description of a tier?

A tier is physical: it runs as its own process or server. A logical grouping of code is called a layer.

Q4Which layer is responsible for displaying data and collecting user input?

The presentation layer is the user interface. It should not contain the rules (business logic) or talk to the database itself.

Q5A note-taking app that runs offline on one laptop and saves to a local file is an example of…

Everything (UI, logic, storage) is on one machine with no network, which is 1-tier.

Part B: 2-tier and 3-tier

Q6In a 2-tier system, the client usually talks directly to:

In 2-tier there is no middle tier: the client program sends SQL straight to the database server. Gateways, queues and caches are N-tier components.

Q7In a 3-tier architecture, which tier should contain most of the business rules?

The application tier is where rules are enforced, because it is under the organisation's control and every client must go through it. The data tier can add constraints, but it is not the main home of the rules.

Q8Why is a 2-tier design risky for a system used over the internet?

Each client connects straight to the database, so the DB is exposed and the connection details sit on every user's device. 3-tier hides the database behind the application tier.

Q9A browser calls a Node.js API, which reads and writes a PostgreSQL database. How many tiers is this?

Browser (presentation) → Node.js API (application) → PostgreSQL (data): the classic 3-tier web application.

Q10A rule in a 3-tier web app is checked in the browser with JavaScript. What else must happen?

Users control their own browser and can bypass any client-side check. Browser checks are for a quick, friendly interface; the server must enforce the rule. "Never trust the client."

Q11Traffic to a 3-tier web app doubles. What is the usual way to scale it?

If the application servers are stateless, you add more of them (horizontal scaling) and a load balancer spreads requests across them.

Part C: N-tier and modern systems

Q12What is the main reason to move from 3-tier to N-tier?

Splitting the middle tier into specialised services lets each part scale, deploy and fail independently. N-tier adds tiers; it never removes servers or exposes the database.

Q13Which component spreads incoming requests across several identical servers?

A load balancer (for example Nginx, HAProxy or a cloud load balancer) sits in front of a tier and distributes traffic so no single server is overloaded.

Q14What is the main purpose of a cache tier such as Redis?

A cache answers repeated reads quickly from memory. The database remains the permanent, authoritative store.

Q15How do microservices usually divide an application?

Microservices are a modern N-tier style: the business tier is split by capability, and each service can be built, deployed and scaled on its own, communicating over APIs or messages.

Q16Which is a real disadvantage of N-tier architecture?

With many tiers and services, finding a fault or deploying safely requires good DevOps tooling. Scalability and cloud hosting are strengths, not weaknesses.

Q17A message queue (for example RabbitMQ or Kafka) in an N-tier system is used to…

Example: after an order is placed, a "send confirmation email" message goes on the queue and an email service handles it later. The user gets a fast response.

Summary

  • 1-tier: all in one program. 2-tier: thick client + database server. 3-tier: presentation, application, data. N-tier: the middle and data tiers split further.
  • In 3-tier and above, the client never talks to the database; business rules are enforced on the server.
  • More tiers buy scalability, flexibility and fault isolation, and cost complexity, money and some latency.
  • Load balancers, API gateways, caches and queues are typical N-tier components; microservices and cloud systems are modern N-tier designs.
