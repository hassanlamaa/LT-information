Security Layers

Explore how different security domains interact and protect information systems. Understand the "weakest link" principle through interactive examples, scenarios and knowledge checks, and see how today's defence-in-depth and zero-trust thinking build on the same layered idea.

Learning objectives

  • Distinguish between the four primary security layers.
  • Explain key components and concerns of each layer.
  • Analyse real-world scenarios to identify the layers involved.
  • Apply the "weakest link" principle to security assessment.

1The layered model

Security is organised in layers, like the layers of an onion around the information you want to protect. Each layer has its own people, tools and failure modes. The innermost layer is the software and data itself; around it sit the day-to-day operations that keep it running, the networks that carry it, and finally the organisation-wide cybersecurity strategy that ties everything together.

Defence in depth
Using several independent layers of controls so that if one fails, another still stops or detects the attacker.
Weakest link
"Global security is always that of the weakest link": an attacker only needs one gap, so overall security is limited by the weakest layer.
Zero trust
The modern refinement: no user, device or network location is trusted by default; every request is authenticated and authorised (NIST SP 800-207).
Analogy

A bank branch has a locked door, a guard, cameras, a vault and a time lock. A robber has to beat all of them. But if the vault code is written on a sticky note, all the other layers barely matter: that note is the weakest link.

Exam tip

Defence in depth and weakest link are two sides of the same idea. Defence in depth is the strategy (stack independent layers); weakest link is the warning (one neglected layer undoes the investment in the others).

2Layer 1: Logical & application security

Definition: security implemented through software, programs and data management to ensure proper functioning and data protection. This is the layer closest to the data: if the application itself is flawed, no firewall can fully compensate.

Secure development

Following "Security by Design" principles, quality coding practices, and thorough security testing (code review, static and dynamic analysis) during development. The OWASP Top 10 lists the most common web flaws, led by Broken Access Control.

Cryptography

Implementing encryption and hashing to ensure data integrity and confidentiality during storage and transmission. Use AES-256 and SHA-256; avoid DES, MD5 and SHA-1. Store passwords with Argon2id or bcrypt.

Access control

Authentication procedures (MFA, ideally passkeys/FIDO2) and authorization mechanisms to ensure only authorised users access specific resources, following least privilege.

Data classification

Categorising data by sensitivity (Normal, Confidential, Secret; many companies use Public, Internal, Confidential, Restricted) and applying appropriate protection measures to each category.

Least privilege is the rule that ties these together: a doctor needs to read and update patient records, not to administer the database server.

Real-world example: hospital records system

Scenario: a hospital uses state-of-the-art encryption for patient data. However, its software was developed quickly with minimal testing, and all doctors share the same admin password.

Logical security issues:

  • Poor development quality: minimal testing leads to undiscovered vulnerabilities.
  • Weak access control: shared admin passwords eliminate accountability; nobody can tell which doctor did what.
  • No least privilege: all doctors have admin access when they only need patient data access.

Outcome: despite strong encryption (one component), the system is vulnerable because of weaknesses in the other logical security components. Encryption protects data at rest, but an attacker who phishes the shared admin password simply logs in and reads everything decrypted.

Common mistake

"We encrypt everything, so we are secure." Encryption only protects against people who do not have the key or a valid login. Most breaches use valid (stolen) credentials or an application flaw, and the application decrypts the data for them.

Knowledge check: Logical security

Q1A company has implemented strong encryption for all data but has not classified data by sensitivity level. Which logical security component is weak?

Data classification is essential for applying appropriate protection measures based on sensitivity. Without it, all data gets the same protection level, which may be insufficient for confidential information or wasteful for normal data.

3Layer 2: Operational security

Definition: ensuring day-to-day functioning through tools, procedures, maintenance and management of IT systems. A system that was secure on launch day becomes insecure within months if nobody patches, monitors and backs it up.

Configuration & update management

Keeping systems properly configured, patched and updated to address known vulnerabilities. Prioritise flaws that are actively exploited, for example those on CISA's Known Exploited Vulnerabilities (KEV) list.

Backup & continuity management

Regular backups, tested restoration procedures, and business continuity planning for disaster recovery. Follow 3-2-1 (3 copies, 2 media, 1 off-site) and keep one offline or immutable copy that ransomware cannot delete.

Incident management

Processes for detecting, responding to and resolving security incidents with proper documentation: preparation, detection and analysis, containment, eradication and recovery, lessons learned.

Log management

Collecting, monitoring and analysing log files for security events, anomalies and forensic investigations, usually centralised in a SIEM (Security Information and Event Management) system.

RTO
Recovery Time Objective: the maximum acceptable downtime.
RPO
Recovery Point Objective: the maximum acceptable data loss, in time (nightly backup = up to 24 h lost).
Change management
Changes are planned, approved, tested and reversible, so "maintenance" does not itself cause an outage.
Real-world example: financial firm outage

Scenario: a financial firm skipped server maintenance to "save costs". No recent backup tests were performed. During peak trading hours, its transaction system fails completely.

Operational security issues:

  • Poor maintenance: skipped maintenance leads to a preventable system failure.
  • Untested backups: recovery procedures are not verified to work when needed.
  • Lack of monitoring: no performance monitoring to predict the impending failure.

Outcome: recovery takes 8 hours instead of the promised 30 minutes (the RTO), causing significant financial losses and reputational damage.

Common mistake

Keeping the only backup on a network share that the same admin account can reach. Ransomware operators steal admin credentials and delete or encrypt backups before launching the encryption. Separate credentials and an offline/immutable copy are essential.

Knowledge check: Operational security

Q2A company performs regular backups but has never tested restoring data from them. Which operational security principle is being violated?

Backups without restoration testing are unreliable. The only way to ensure backups work is to periodically test restoration procedures. Many organisations discover their backups are corrupted or incomplete only during a real crisis.

4Layer 3: Telecommunications security

Definition: securing end-to-end network connectivity and infrastructure to ensure reliable, protected communication: LAN, Wi-Fi, WAN links, internet access, VPNs and the devices that run them (routers, switches, firewalls).

Network architecture security

Designing network topology with security zones (for example a DMZ for public servers), segmentation (VLANs, internal firewalls) and defence-in-depth principles.

Access controls

Network access control (802.1X), firewalls and intrusion prevention systems (IPS) to filter and monitor traffic.

Transmission security

Encrypting data in transit with TLS 1.3/1.2 (SSL and TLS 1.0/1.1 are deprecated), VPNs (IPsec, WireGuard), WPA3 for Wi-Fi, and secure routing practices.

Network management

Monitoring network performance, availability and security events through centralised management tools, using secure protocols (SSH, SNMPv3).

Why WPA3

WPA3-Personal replaces the WPA2 pre-shared-key handshake with SAE (Simultaneous Authentication of Equals), which resists offline password-guessing attacks on captured handshakes and provides forward secrecy. Open networks can use OWE ("Enhanced Open") so traffic is encrypted even without a password.

Real-world example: e-commerce platform

Scenario: an e-commerce company uses strong TLS encryption for customer transactions. However, its internal network has no segmentation, and employee workstations are on the same network segment as database servers.

Telecommunications security issues:

  • Poor network segmentation: a flat network allows lateral movement if one device is compromised.
  • Weak internal controls: no internal firewalls between different network zones.
  • Over-reliance on perimeter security: strong external encryption does not protect against internal threats.

Outcome: when an employee's workstation is infected with malware, attackers can easily move to database servers and steal customer data despite strong external encryption. A zero-trust design (workstations may only reach the database through the application, with every connection authenticated) would have blocked that path.

Common mistake

Thinking TLS protects the data everywhere. TLS protects data in transit between two endpoints. Once it arrives on the server, protection depends on the other layers.

Knowledge check: Telecommunications security

Q3A company implements excellent encryption for data transmission but does not segment its internal network. Which telecommunications security principle is weak?

Network segmentation is a critical architectural security control that limits lateral movement if a system is compromised. Without segmentation, attackers who breach one system can easily access others on the same network, regardless of strong transmission encryption.

5Layer 4: Cybersecurity integration

Definition: the strategic integration of all security layers to create a comprehensive security posture and organisational resilience. This is where management, people and frameworks come in.

Integration & coordination

Ensuring all security layers work together cohesively rather than as isolated silos: developers, operations and network teams share alerts, priorities and responsibility.

Weakest link principle

Recognising that overall security strength equals the strength of the weakest component across all layers.

Risk management

Balancing security investments based on threat assessment (dangerousness × probability, also written impact × likelihood).

Organisational responsibility

Establishing security as everyone's responsibility, not just the IT department's job, with leadership accountable for it.

Risk management worked example

Score each risk on 1–5 for dangerousness (impact) and probability (likelihood), then multiply:

RiskLayerProbabilityDangerousnessScore

The budget goes first to phishing-resistant MFA plus awareness training, then patching the VPN. Treating risks in score order is how the weakest-link principle becomes an action plan.

Frameworks for integration

NIST CSF 2.0 (2024)

Six functions: Govern (new), Identify, Protect, Detect, Respond, Recover. "Govern" is exactly this layer: strategy, roles, policy and supply-chain risk.

ISO/IEC 27001:2022

Certifiable management system for information security. Its 93 Annex A controls are grouped into organisational, people, physical and technological themes, which map neatly onto the layers on this page.

Real-world example: manufacturing company

Scenario: a manufacturing company invests heavily in network security (firewalls, intrusion detection) but neglects employee security training. It also has excellent backup systems but poor access controls on its design servers.

Cybersecurity integration issues:

  • Inconsistent security investment: strong in some areas, weak in others.
  • Failure to recognise the weakest link: despite strong network security, human factors create vulnerabilities.
  • Lack of holistic view: treating security as a set of isolated controls rather than an integrated system.

Outcome: an employee falls for a phishing email, giving attackers credentials that bypass the strong network security. Attackers then access design servers because of weak access controls, stealing proprietary manufacturing designs. Training plus phishing-resistant MFA (passkeys) would have broken the first step; least privilege on the design servers would have limited the second.

Knowledge check: Cybersecurity integration

Q4A company has strong logical, operational and telecommunications security, but no employee security training programme. According to the "weakest link" principle, what is its overall security level?

The "weakest link" principle states that overall security is determined by the weakest component. Since human factors (lack of training) are among the most exploited weaknesses (phishing is a leading entry point), this gap can undermine all other controls. In practice, defence in depth can soften the damage, but the principle tells you where to invest next.

6Controls across the layers

Every layer uses controls of three kinds (administrative, technical, physical), and each control acts at a moment: before (preventive), during (detective) or after (corrective) an incident.

PreventiveDetectiveCorrective
AdministrativeSecurity policy, training, data classification rulesAudits, log reviewsIncident response plan, disciplinary action
TechnicalMFA, firewall, encryption, network segmentation, patchingIDS, SIEM alerts, EDR, file-integrity monitoringRestore from backup, quarantine malware, failover
PhysicalLocked server room, badge accessCCTV, door alarmsFire suppression, replacing damaged equipment
Key idea

A strong design has preventive, detective and corrective controls in every layer. Prevention alone fails silently; detection without correction just watches the damage.

7Final quiz

Quiz: Security layers

Q5Which layer does SQL injection in a web application mainly belong to?

Injection is a flaw in the application code (OWASP Top 10, "Injection"). It is fixed by parameterised queries and input validation in the software.

Q6A server is compromised because a published patch was never installed. Which layer failed?

Patch and update management is a day-to-day operational task. The flaw was in the software, but the failure was in operations not applying the fix.

Q7Which is the most secure choice for an office Wi-Fi network today?

WPA3 uses SAE, which resists offline password guessing. WEP and WPA-TKIP are broken; WPA2 is acceptable only with AES and a strong secret.

Q8A network administrator still manages switches with Telnet. What should replace it?

Telnet sends passwords in clear text. SSH encrypts and authenticates the session. The other options are also insecure clear-text protocols.

Q9What does "defence in depth" mean?

Defence in depth stacks different controls (application, operations, network, people) so an attacker must defeat several, and each layer can detect them.

Q10Which statement best describes zero trust?

Zero trust (NIST SP 800-207) removes the idea of a trusted internal network, which is exactly what failed in the flat-network e-commerce scenario.

Q11Risk X has probability 2 and dangerousness 5. Risk Y has probability 4 and dangerousness 3. Which score is higher?

Multiply, do not add: X = 2 × 5 = 10, Y = 4 × 3 = 12. Y is treated first.

Q12A SIEM raising an alert about many failed logins is which type of control?

It is software (technical) and it notices an event in progress (detective). Account lockout after the alert would be preventive or corrective.

Q13True or false: because an e-commerce site uses TLS 1.3, its customer database is protected even if an internal workstation is infected.

TLS only protects data in transit between browser and server. An infected internal machine on a flat network can reach the database directly: a network-architecture problem.

Q14In NIST CSF 2.0, which function corresponds most closely to Layer 4 (cybersecurity integration and strategy)?

Govern, added in CSF 2.0 (2024), covers strategy, roles and responsibilities, policy and supply-chain risk: the organisation-wide integration this layer describes.

Summary

  • Layer 1, logical & application: secure development, cryptography, access control (least privilege, MFA), data classification.
  • Layer 2, operational: configuration and patch management, tested backups (3-2-1 plus offline/immutable), incident management, log management; RTO and RPO.
  • Layer 3, telecommunications: segmentation and security zones, firewalls/IPS, TLS 1.3, VPN, WPA3, secure management protocols.
  • Layer 4, cybersecurity integration: coordination, risk management (dangerousness × probability), everyone's responsibility, frameworks such as NIST CSF 2.0 and ISO/IEC 27001:2022.
  • Defence in depth stacks independent layers; zero trust removes implicit trust in the network.
  • Remember: "Global security is always that of the weakest link." Security is a process, not a product.
